# Security model

The registry is private by default. R2 credentials are server-side only, the bucket remains private, and repository authorization is checked before content existence is revealed. Browser authentication uses secure HttpOnly SameSite cookies; Docker automation uses short-lived Bearer tokens minted from revocable, scoped credentials. Browser users may rotate their password and add authenticator-app TOTP two-factor authentication. Password changes revoke all browser sessions; enabling TOTP revokes other sessions while retaining the session that confirmed setup.

The storage abstraction deliberately separates an immutable object key from repository authorization. A content-addressed digest is not itself permission to read the bytes: later database relationships must prove that the requested repository is allowed to reference the object.

The current foundation validates configuration, rejects path traversal in the local store, atomically replaces local objects, adds request IDs to responses/log context, and avoids returning internal errors to clients. Passwords use Argon2id, TOTP uses RFC 6238 HMAC-SHA1 with a small clock-skew window, and TOTP secrets are never returned by status or login responses. The persisted authentication snapshot contains the TOTP secret so the feature survives restart; access to that runtime snapshot and its backups must therefore remain restricted like other server-side credentials.
